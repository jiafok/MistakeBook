## 2. V1.1 新增攻击面分析

工作台把大量判定数据交给客户端渲染，因此新增以下不可信输入：

| 输入 | 来源 | 风险 | 控制措施 |
| --- | --- | --- | --- |
| `x` / `y` / `width` / `height` | 前端提交 | 伪造区域可让错题指向错误内容，或造成越界渲染 | 服务端以 `question_regions` 的存储值为准；客户端提交的几何数据不作为权威 |
| `wrong_probability` | AI 服务 / 前端 | 前端抬高概率可诱导自动预选 | 概率由服务端计算并存储；接口回传仅供展示 |
| `is_selected` | 前端 | 直接决定收录范围 | **禁止信任**；以服务端根据 `question_id` 列表重新校验的结果为准 |
| `paper_id` / `question_region_id` | URL 与请求体 | IDOR 收录他人题目 | 每次访问均校验 `papers.user_id == current_user` |
| `commit` 批量规模 | 前端 | 资源耗尽、绕过单页限制 | 服务端强制单次批量上限，并与配额/速率限制联动 |

### 2.1 关键不信任声明

> 客户端提交的任何字段都必须被视为“请求意图”，而不是“已验证事实”。服务端的权威数据来源只有三处：`papers` 归属、`question_regions` 几何与概率、`questions` 内容。

## 3. 越权（IDOR / 权限绕过）

| 编号 | 场景 | 期望 | 验证方法 |
| --- | --- | --- | --- |
| SEC-01 | 用户 A 请求用户 B 的 `paper_id` 区域列表 | 404 或 403，不泄露存在性 | 接口测试替换 id |
| SEC-02 | 提交时混入他人 `question_id` | 整批拒绝或该条失败，不得静默收录 | 构造混合批次 |
| SEC-03 | 通过 `question_region_id` 反查他人试卷 | 拒绝 | 直接请求 |
| SEC-04 | 家庭成员角色越权读取 | 按确认后的权限模型强制校验 | 角色矩阵测试 |
| SEC-05 | 未登录访问工作台路由 | 重定向登录，接口返回 401 | 直接请求 |

实现要点：所有查询从 `current_user` 出发做 `JOIN`，而不是先按 id 取记录再比对，避免“先读后判”导致的时序问题。

## 4. 客户端数据篡改

| 编号 | 攻击 | 后果 | 控制 |
| --- | --- | --- | --- |
| SEC-10 | 修改请求体 `wrong_probability = 100` | 试图压过用户选择或影响统计 | 服务端忽略该字段，使用存储值；统计使用 `wrong_probability_snapshot` |
| SEC-11 | 提交越界坐标（负数、超出页图） | 前端渲染异常、指向错误区域 | `CHECK` 约束 + 应用层边界校验 |
| SEC-12 | 提交 `is_selected=true` 但未点提交 | 试图绕过确认 | 收录只由 `commit` 接口触发，无其他写路径 |
| SEC-13 | 直接调用内部任务接口触发重算 | 资源消耗、状态混乱 | 任务接口不对外暴露，或需管理员权限 |

## 5. XSS

识别文本来自用户上传的图片内容，属于不可信数据，且会显示在浮层、详情页与导出中。

| 编号 | 控制 |
| --- | --- |
| SEC-20 | 前端禁止 `v-html` 直接渲染 OCR 文本；必须转义或用文本节点 |
| SEC-21 | 若需富文本展示公式，使用受限渲染器并禁用脚本/事件属性 |
| SEC-22 | 导出 PDF/Word/Markdown 时对文本做各自格式的转义，防止 Markdown 注入任意链接/HTML |
| SEC-23 | 页图 URL 使用签名或受控路由，禁止 `javascript:` 等协议注入 |

## 6. CSRF 与认证

| 编号 | 控制 |
| --- | --- |
| SEC-30 | 若使用 Cookie 会话：设置 `HttpOnly`、`SameSite=Lax/Strict`、`Secure`（HTTPS 时） |
| SEC-31 | 所有写接口校验 CSRF token 或使用同源 `Origin`/`Referer` 校验 |
| SEC-32 | 若使用 Bearer token：不放在 localStorage 以外的可读位置需权衡 XSS 风险，架构阶段定案 |
| SEC-33 | 登录、提交等敏感接口做速率限制 |
| SEC-34 | 会话固定防护：登录后重建会话 ID |

## 7. 文件上传

| 编号 | 控制 |
| --- | --- |
| SEC-40 | 校验扩展名 + 文件头（magic bytes），不信任 `Content-Type` |
| SEC-41 | 限制单文件大小、PDF 页数、图片像素总量 |
| SEC-42 | 存储时使用随机键，不使用用户原始文件名作为路径 |
| SEC-43 | 上传目录不可执行；通过应用受控路由提供访问 |
| SEC-44 | PDF/图像解析放在受限环境，防止解析器漏洞导致 RCE |
| SEC-45 | 拒绝 zip 炸弹式或多层嵌套文档 |

## 8. Prompt Injection

OCR 文本会作为 AI 分析的输入，因此试卷内容可能包含针对模型的指令。

| 编号 | 控制 |
| --- | --- |
| SEC-50 | 系统提示与文档内容严格分离，文档内容置于明确的数据边界内 |
| SEC-51 | 模型输出按结构校验（JSON schema），拒绝非预期字段 |
| SEC-52 | 模型不得拥有工具调用权限；分析是纯文本/结构化输出任务 |
| SEC-53 | 模型输出不得直接影响权限、收录或删除操作 |
| SEC-54 | 对输出中的链接、HTML 做净化后才展示 |

## 9. 批量接口滥用与资源耗尽

| 编号 | 控制 |
| --- | --- |
| SEC-60 | `commit` 单批上限与请求频率限制 |
| SEC-61 | 区域查询限制每页返回数量 |
| SEC-62 | 重算接口限制次数与并发，防止刷任务 |
| SEC-63 | 长任务设置超时与取消能力，避免僵尸任务占资源 |

## 10. 数据与隐私

| 编号 | 控制 |
| --- | --- |
| SEC-70 | 日志不记录题目原文、令牌、密钥；如需排障记录哈希或 id |
| SEC-71 | 第三方 AI 调用前告知提供方；密钥不得回显 |
| SEC-72 | 删除账号/试卷时明确关联数据处置，避免残留可访问文件 |
| SEC-73 | 备份文件加密，且与应用同权限保护 |
| SEC-74 | 未成年人数据处理策略需发布前确认（产品/法务） |

## 11. 审计方法

1. 静态检查：搜索 `v-html`、原生 SQL 拼接、`subprocess` 调用点。
2. 接口越权矩阵测试：以低权限账号遍历所有资源 id 路径。
3. 篡改测试：用拦截工具修改请求体字段，确认服务端忽略不可信字段。
4. 上传绕过测试：改扩展名、改 magic bytes、构造畸形 PDF。
5. 依赖扫描：定期检查 OCR/PDF 解析库的已知漏洞。

## 12. V1.1 安全 Review

- 已确认：V1.1 未引入“自动收录”这一最危险的写路径；收录仅由单一接口触发。
- 已确认：客户端可伪造的字段（坐标、概率、选择态、归属 id）均有明确服务端控制点。
- 已确认：OCR 文本进入前端与 AI 的路径均有转义与边界控制要求。
- 待确认：会话令牌存放方式、家庭成员权限矩阵、单批上限具体值。
- 结论：**无阻断性安全问题；上线前需完成越权矩阵与篡改测试。**
